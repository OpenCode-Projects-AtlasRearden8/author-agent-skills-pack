# Workflow Notes for the Newsletter-Draft Assistant

Per issue:

1. Read `newsletter/planner.md`; pick one theme and slot the other ideas into "future planners."
2. Sweep the local sources the author designates (`notes/**`, `canon/factsheet.md`, `data/launch-dates.md`, `newsletter/*/sent.md`).
3. Write `newsletter/<yyyy-mm>/draft.md` using the planner skeleton, 400–600 words, voice: plain, warm, no hype.
4. Mark every unverified claim `[check]`, every cuttable block `[optional]`, and wrap model-assisted text in `[begin draft]/[end draft]` comments.
5. Write `links.md` alongside the draft; every link carries its one-line reason.
6. After the author sends, they (not the agent) fill `sent.md`. Next issue consumes `sent.md` lines as "what happened" material.

Hard rules: no sending, no scraping subscriber data, no names of readers, no invented launch dates (a date without a source gets `[check]`).
